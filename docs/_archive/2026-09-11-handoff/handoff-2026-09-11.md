```bash
# 抽 APNG 0/3/6s 帧, 看是否完整 + 透明
ffmpeg -i app/public/assets/octopus/v2/pretend-busy.png -vf "select=eq(n\,0)" -vframes 1 /tmp/0s.png

ffmpeg -i app/public/assets/octopus/v2/pretend-busy.png -vf "select=eq(n\,99)" -vframes 1 /tmp/6s.png

# alpha_composite 测试透明 (类似 BiRefNet 实战的方法)
python3 -c "
from PIL import Image
for t in ['0s', '3s', '6s']:
    img = Image.open(f'/tmp/{t}.png').convert('RGBA')
    red_bg = Image.new('RGBA', img.size, (255, 0, 0, 255))
    composite = Image.alpha_composite(red_bg, img)
    composite.save(f'/tmp/{t}_red.png')
    print(f'{t}: alpha range = {img.split()[3].getextrema()}')
"
# alpha range (0, 255) 表示透明通道完整
```

### 2.4 失败排查 (跑出来有问题时)

| 现象 | 根因 | 解决 |
|------|------|------|
| `FileNotFoundError: BiRefNet` | 模型未下载 | 重跑 §2.1 第 3 步 |
| `CUDA out of memory` | VRAM 不够 (5.5GB 峰值, RTX 3060 12GB 够用) | 关闭其他 GPU 进程 / 降 `--batch` |
| 整图绿残留 > 1% | CorridorKey 物理 unmixing 没生效 | 检查 torch 版本 (要 2.6.0+cu124) / 重跑 |
| 放大镜/帽反光"白方块" | forehead_white_mask ROI 没生效 | 验证 ROI y=50-80 x=70-110 范围 |
| prop 淡出帧 prop 绿色 | borrow+recolor 没生效 | 检查 median 参考帧数量, 加 `--num-references 8` |
| 末帧循环断裂 (8 触手/圆耳偏离) | v10-final 没治本末帧 | 接受, 在桌宠实际使用 1 帧过渡即可 (用户视觉无感) |

## 4. 打包项目方法 (跨平台 release)

### 4.1 release-plugin.sh 详解

**位置**: `scripts/release-plugin.sh` (已 commit)
**用法**:
```bash
bash scripts/release-plugin.sh            # 完整: 构建 + 产物 + 冒烟 + 可选 bundle
bash scripts/release-plugin.sh --no-bundle  # 快: 跳过 .app/.deb/.msi bundle
```

**输出 (4 步)**:
1. `cargo tauri build --no-bundle` 编译 release (1-2 分钟)
2. 拷贝到 `bin/octopus-pet.${KERNEL}.bin` (KERNEL ∈ {macos, linux, windows})
3. 组装 `dist/octopus-pet-plugin/` 整包 (plugin.json + mcp.json + skills/ + bin/ + README + CHANGELOG + LICENSE)
4. **冒烟**: MCP initialize + tools/list, 验证产物可用

**关键**:
- 必须走 `cargo tauri build`, **不要**裸 `cargo build` (会跳过 asset 嵌入, binary < 5MB = 白框)
- 自动检测 host kernel: macOS / Linux / Windows
- 产物跨平台 portable, **每个平台都要跑一次** (macOS 端出 macos.bin, Linux 端出 linux.bin, Windows 端出 windows.bin)

### 4.2 跨平台 release 工作流 (3 机器 × 3 产物)

| 机器 | 跑什么命令 | 产物 | 提交 |
|------|----------|------|------|
| macOS M1 Pro | `bash scripts/release-plugin.sh` | `bin/octopus-pet.macos.bin` (~15MB) | `git add bin/octopus-pet.macos.bin && git commit` |
| Linux x86_64 NUC | `bash scripts/release-plugin.sh` | `bin/octopus-pet.linux.bin` (~17MB) | `git add bin/octopus-pet.linux.bin && git commit` |
| Windows 11 (如有) | `bash scripts/release-plugin.sh` | `bin/octopus-pet.windows.bin` (~17MB) | 同上 |

**注**: 同一份源代码, 3 机器各跑一次, 产 3 平台 binary。每个 binary 内嵌 5-8 个 v2 APNG (vite build 把 `app/public/assets/octopus/v2/*.png` 嵌进 frontendDist, generate_context! 读)。

### 4.3 集成到 commit + push 流程

```bash
# 场景: macOS 端跑完, 准备提交
git add app/public/assets/octopus/v2/pretend-busy.png  # 新 APNG
git add scenes.json                                      # 加 5 entry
git add app/src/state/scene-registry.generated.ts        # build-scene-registry 生成
git add src-tauri/src/scene_registry_generated.rs        # build-scene-registry 生成

git commit -m "feat(v2): +5 场景 APNG (pretend-busy / friday-5pm / stay-late / treat-milk-tea / breakdown)"

# 跑 release
bash scripts/release-plugin.sh
git add bin/octopus-pet.macos.bin
git commit -m "release(macos): v2.3 macOS 产物 (+5 场景)"
git push origin main

# 通知 Linux / Windows 端: "拉新 commit, 跑 release-plugin.sh 出 platform 产物"
```

### 4.4 分发 dist/octopus-pet-plugin/ (可选)

`scripts/release-plugin.sh` 自动生成 `dist/octopus-pet-plugin/` 整包 (~15MB, 含 plugin.json / mcp.json / skills/ / bin/ / README.md / CHANGELOG.md / LICENSE)。

**用法**:
```bash

cd dist && tar -czf octopus-pet-plugin-v2.3.tar.gz octopus-pet-plugin/

# 2. 加载: mcode 添加插件 → 指向 octopus-pet-plugin/ 目录
#    OR: 解压到 ~/.mavis/plugins/ 目录, mcode 自动发现
```
